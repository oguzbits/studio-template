# Runde 2b (UI-Look) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Marketing, Auth, App-Shell und Fehlerseiten auf das Token-System aus ui-analyse §5 heben und dabei Mobil-LCP < 2,5 s, Script < 350 KB und a11y 100 erreichen.

**Architecture:** Tokens/Fonts zentral in `styles/shadcn-ui.css` und `lib/fonts.ts`; Marketing-Seiten ohne Base-UI im Erstbundle (eigene schlanke Komponenten unter `app/(marketing)/_components/`); Auth-Logik in `packages/features/auth` bleibt, nur Markup; Client-importierte Configs ohne zod-Laufzeit.

**Tech Stack:** Next.js 16 App Router, Tailwind v4, `@kit/ui` (shadcn auf Base UI), next-themes, next/font (Geist), Vitest, Playwright.

**Spec:** [docs/superpowers/specs/2026-10-23-runde-2b-ui-design.md](../specs/2026-10-23-runde-2b-ui-design.md)

## Global Constraints

- UI-Texte Englisch; nur Rechtsseiten Deutsch. Komponenten aus `@kit/ui`, Icons Lucide.
- Tokens exakt aus ui-analyse §5 (OKLCH-Tabelle); Teal-Text-Variante L 0.53 (≥ 4,5:1 auf Hell).
- Radius `--radius: 0.5rem`, Karten 12 px, Controls 40 px, Hero-CTA/Auth 48 px.
- H1 64 px desktop / 40 px mobil, Line-Height 1.05, −0,035 em, Gewicht 600.
- Keine Fade-/Slide-In-Animationen auf LCP-Elementen (H1, Auth-Formular).
- Links nach `/auth/*` auf Marketing-Seiten mit `prefetch={false}`.
- `data-test`-Attribute in `packages/features/auth` bleiben unverändert (E2E).
- Kein neues npm-Paket außer der Font über `next/font/google` (kein Download-Paket nötig).
- `apps/web/.env` (getrackte Public-Defaults) ist für Agenten per Hook gesperrt: Theme-Default `system` daher
  in `app.config.ts` als Fallback; die Zeile `NEXT_PUBLIC_DEFAULT_THEME_MODE` in `apps/web/.env` stellt der Nutzer
  um (in der Abschlussmeldung nennen).
- Jeder Task endet mit `pnpm --filter web typecheck && pnpm --filter web lint && pnpm --filter web exec vitest run`
  grün; `pnpm check` vor dem Push.

## Review Focus

- Nur ein Auth-Verfahren aktiv (nur Passwort, nur Magic Link, nur OAuth) → keine leeren Tabs, kein verwaister
  Divider. Test: Task 5.
- `billing.json`-Produkt ohne `features` oder `mode: 'payment'` → Karte zeigt Preis „one-time“, keine leere
  Liste. Test: Task 2 (`highlightedProduct`) + Sichtprüfung Task 4.
- Leere `faq` → keine FAQ-Sektion auf `/` und `/pricing`, `/faq` bleibt 404. Sichtprüfung Task 4.
- Mobil 390 px: Header-Menü per Tastatur öffnen/schließen, Hero-Mock bricht das Layout nicht (kein
  horizontales Scrollen). Sichtprüfung Task 3/4.
- Dunkel-Modus: alle Texte ≥ 4,5:1, Fokus-Ring sichtbar. Lighthouse a11y Task 7.
