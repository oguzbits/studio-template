# Runde 1 (P0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Audit-Maßstab + die vier P0-Lücken (Branding, Header, Env, Stripe-Automatik) schließen.
**Architecture:** Reine, getestete Funktionen in `.mjs`-Modulen (von `next.config.mjs` und Skripten importierbar),
I/O dünn darum. Inhalte aus `studio.config.ts`, Produktdaten aus `config/billing.json`.
**Tech Stack:** Next.js 16.4.2, Vitest, Zod, Node 26 (Skripte), Stripe REST, Lighthouse 12 via `pnpm dlx`.
**Spec:** `docs/superpowers/specs/2026-10-22-runde-1-p0-design.md`
**Ausführung:** nativ in der Hauptsession (Nutzer: „mach mit allem weiter“), Gesamtreview am Ende durch frischen Agenten.

## Global Constraints

- Keine neue Abhängigkeit außer `lighthouse@12` per `pnpm dlx` (freigegeben).
- UI-Texte Englisch, Doku/Skriptausgaben Deutsch. Meldungen nennen nie Secret-Werte.
- `.env`-Dateien (außer `.env.example`) nicht lesen/schreiben.
- Jeder Schutz-Test muss rot werden, wenn der Schutz fehlt.
- `pnpm check` grün vor jedem Push; kleine Conventional Commits.

## Review Focus

1. Stripe-Schritt doppelt ausgeführt → keine doppelten Produkte/Preise/Endpoints (Lookup über Metadaten/`lookup_key`).
2. `sk_live_` in `.env.shared` → `studio:new` bricht vor jeder Stripe-Anlage ab.
3. CSP blockiert Supabase-Auth (wss/https), Stripe-Redirect aus Server Action oder Analytics → Report-Only-Probe.
4. Env-Prüfung im `build:test` (CI, `pnpm check`) darf nicht greifen; im Vercel-Build schon.
5. `/faq` bei leerer FAQ → 404 und nicht in Sitemap/Navigation.
