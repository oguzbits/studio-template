# Runde 2a (P1 ohne UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Erst-Setup und Diagnose per Befehl, ehrlicher Resend-Hinweis, Rate-Limit für die Warteliste, schnellere Mobil-Seiten.

**Architecture:** Neues Tooling-Modul `studio-tokens.mjs` (Key-Liste + Live-Checks) trägt `studio:setup` und
`studio:doctor`. Rate-Limit als Security-definer-Funktion in Postgres, aufgerufen über den Admin-Client aus
`lib/rate-limit.ts`. Performance wird gemessen (`studio:audit`) statt geraten.

**Tech Stack:** Node 22 ESM-Skripte (Vitest in `tooling/scripts`), Next.js 16, Supabase/Postgres + pgTAP, dotenvx.

**Spec:** [docs/superpowers/specs/2026-10-22-runde-2a-p1-design.md](../specs/2026-10-22-runde-2a-p1-design.md)

## Global Constraints

- Secrets nie ausgeben, loggen oder in Fehlermeldungen einbauen; nur Key-Name + HTTP-Status.
- `.env.shared` nur über `dotenvx get`/`dotenvx set` (Argument-Array via `execFileSync`, keine Shell-Strings).
- Tooling-Texte Deutsch (wie `studio:new`/`studio:audit`), UI-Texte Englisch, hart codiert wie im bestehenden
  `waitlist-form.tsx` (kein next-intl-Umbau).
- Neue Tabelle/Funktion nach AGENTS.md-Konventionen (RLS, `revoke`, `search_path = ''`), danach `supabase:typegen`.
- Rate-Limit Warteliste: **5 pro IP pro 3600 s**; abgelehnt → `{ ok: false, error: 'rate-limited' }`.
- Performance-Ziel: LCP mobil < 2500 ms, Script-Transfer < 350 KB auf `/`, `/pricing`, `/auth/sign-in`.
- Jeder Test einer Schutzfunktion muss rot werden, wenn der Schutz fehlt (je Task genannt).
- Gate vor jedem Push: `pnpm check`. Commits klein, Conventional Commits, Attribution-Zeile.

## Review Focus

1. **Resend-Key nur mit Sende-Recht:** `GET /domains` liefert 401 `restricted_api_key` → Key gilt als gültig,
   Domain-Status „unbekannt“ (Warnung), nicht „ungültig“. Test in Task 1.
2. **Gespoofte IP:** Client setzt `x-forwarded-for: 1.2.3.4` selbst. Auf Vercel ist `x-real-ip` vom Proxy
   gesetzt → `x-real-ip` hat Vorrang vor dem ersten XFF-Eintrag. Test in Task 5.
3. **Rate-Limit-DB down:** RPC-Fehler → Anmeldung geht durch (fail open) und wird geloggt, kein 500. Test in Task 5.
4. **Setup-Abbruch (Ctrl+C) oder leere Eingabe bei Pflicht-Key:** kein halber Wert in `.env.shared`; Key bleibt
   leer und taucht in der Abschlussliste als „fehlt“ auf. Test (`nextAction`) in Task 2.
5. **Doctor ohne `.env.shared` / ohne Docker:** klare `✗`-Zeile statt Stacktrace, restliche Prüfungen laufen
   weiter. Test (`runLocalChecks` mit fehlschlagenden Probes) in Task 3.
